## [Unreleased]

### Added
- Phase 09: rollout. MeetingMaster3, chessloopDeploy, OCC and YTPL2 now carry the hands-off contract (`PHX-CONTRACT: 1`, step 0, the "Hands-off mode" section, block-with-question, Risk rule, ADR-0004 git rules, Gate column, an ADR and a vault log line each; `phx plan` reports `Contract: 1` for all four). User-level slash command `~/.claude/commands/phx.md` (`/phx status|run|preflight [repo]`). The skill and playbook gained a "Migrating to the hands-off contract" checklist. Plan fixtures refreshed to the migrated versions (ADR-0018).
- Phase 08: `phx preflight [<repo>] [--dry-run | --check | --record]`. One interactive Claude Code session on `opus` (through `ai-provider run`, with the instructions in `--append-system-prompt-file` and a kickoff message; no `PHX_AUTO`, normal permissions) asks Nick everything the remaining phases will predictably need, records the answers (Owner questions `Decided <TS>: … (phx preflight)`) and ADRs, confirms Gates (adding the Gate column if missing) and commits `docs(plan): phx preflight <TS>`. Before launching, PHX refuses when a phase is `🔄`, a supervisor runs, the checkout is off `main` or nothing is left, and builds the context at no token cost: remaining phases with a suggested Gate, open and deferred questions, heuristic leads from the remaining prompts, tool and `gh auth` checks. `phx preflight --record` writes and commits `.phx/preflight.json` (a fingerprint of the phase table's definitions, the questions seen, phases covered, unresolved items). `phx run` warns when it is missing or stale (rules `preflight_missing`, `preflight_stale`, `preflight_invalid`), `--require-preflight` refuses; `phx status` shows it. The session prompt is `prompts/PHX_preflight.md`, packaged into the wheel. ADR-0017; spec amendment R20. 45 new tests.
- Phase 07: the supervisor. `phx run [<repo>] [--detach] [--pause-after NN] [--until NN] [--max-phases N] [--dry-run]` runs a plan hands-off: it re-reads the plan from `main` each round, finishes a pending usage-limit wait, resumes a `🔄` phase (its recorded session with `--resume`, after checking no Claude session holds it), resumes a `⛔` phase once its questions are answered, or starts the next eligible phase; applies Gates (`owner` never started, `review` pauses after); launches `/phase NN --auto` and acts on Phase 06's decision (next phase, pause, wait, resume, fresh retry). Usage-limit waits sleep until the reset time + 2 min or a 30 min…6 h back-off, re-check `ai-provider get` every 5 min (a switch to OpenRouter resumes at once), probe with one `haiku` turn, survive suspend and restarts. `phx resume` clears a pause; `phx status [<repo>] [--json]`; `phx stop` (SIGTERM, session stopped, phase left resumable); `phx log [-f] [--json] [-n N]`; `phx answer <repo> <#> "<answer>"` commits `Answered <TS>: …` to the plan on `main`. New modules `locks.py` (contract §8 `flock` locks), `state.py` (atomic `state.json`), `notify.py` (silent `notify-send`), `vault.py` (run summary in the Obsidian note's Log), `detach.py` (`systemd-run --user` with an env allowlist). S1 enforced (repo under `$PHX_WORK_ROOT`/`~/Work`, not root). `run_session` gains `cancel` and `on_start`; `plan.set_question_status`. Test fakes: a scripted phase agent for the fake `claude`, a fake `notify-send`, a provider-switch file for the fake `ai-provider`. ADR-0016; spec amendment R19. 375 tests (39 more than Phase 06). Installed for daily use with `uv tool install --editable` (documented in OSMods).
- Phase 06: `phx.verify`, `phx.recover` and `phx.triage`. `verify_phase` checks what a phase left on `main` (status, branch merged and deleted, worktree removed, Phase Log entry with its Timeline, main checkout on `main` and clean against a pre-launch baseline, optional push state) and runs the plan's test commands in a temporary clean clone of `main` without a shell (an interpreter for `&&`, `cd`, `NAME=value`, quotes and `**` globs; config key `test_timeout_s`); CL-style commands naming paths the repo lacks are skipped with a note. It compares the `PHX-RESULT` line with the repo and reports `needs_review` on any disagreement. `recover.handle_outcome` repairs a missing `⛔` commit (the only repair, plan file only, `chore(plan): phase NN blocked (recorded by phx)`), verifies, applies the decision table (next phase, pause, wait, resume the same session, fresh session; timeout/crash ladder of one resume then one fresh run), looks for a live Claude process in the phase worktree or the main checkout before any retry (`check_resumable` for R14), and logs `verify`, `repair`, `triage` and `decision` events. `triage.summarize` writes a ≤ 150-word summary with one tool-less `haiku` turn on blocks and failures. `runner.build_argv`/`run_session` gain `permission_mode` and `extra_args`; `plan.set_status_cell`. ADR-0015; spec amendment R18. 102 new tests.
- Phase 05: `phx.runner` and `phx.classify`. `run_session` launches `ai-provider run -p … --model <alias> --permission-mode bypassPermissions --output-format stream-json --verbose --session-id <uuid>` (or `--resume <id>`) in the repo, with `PHX_AUTO=1` and without `ANTHROPIC_MODEL`, in its own process group. It falls back to `claude` with a logged warning, logs a provider snapshot (OpenRouter mapped model from an allowlist, secrets never logged) and passes `--max-budget-usd` only on OpenRouter with a configured cap. It writes the redacted stream to `sessions/<phase>-<n>.jsonl`, enforces idle and wall-clock timeouts (`idle_timeout_s`, `wall_timeout_s` in `.phx/config.toml`; SIGTERM, then SIGKILL the group), totals tokens and cost from the `result` event and logs `launch`/`session_end`. `classify` maps every ending to `complete`, `blocked`, `refused`, `no_result`, `usage_limit` (reset time from `rate_limit_event.resetsAt` or the `You've hit your … · resets …` text), `auth_error`, `provider_error(kind)`, `timeout` or `crash`. `probe()` is a one-turn `haiku` capacity check. Fake `claude` and `ai-provider` executables in `tests/fakes/` and 16 labelled stream fixtures (real, real-text, documented, synthetic). ADR-0009 accepted with evidence; ADR-0014; spec amendment R17. 91 new tests; 100 % branch coverage of `classify.py`.
- Phase 04: `phx.plan`, a read-only plan parser and eligibility engine. Reads everything from `main` (plan, prompts, shared instructions, `phase.md`, `.phx/config.toml`); finds `<PREFIX>_IMPLEMENTATION_PLAN.md` or legacy `IMPLEMENTATION_PLAN.md`; parses the phase table by header name (lettered IDs and ordering, status from icon or word, model → `opus`/`sonnet`/`haiku`/`fable`, dependencies, Gate from column, prompt header or publishing inference); Owner questions (open iff Status starts with `Open`); the `PHX-CONTRACT` marker; the test command; live `phase-*` branches and worktrees with last commit and uncommitted count; drift as `/phase status` defines it; `next_eligible` with a reason for every other phase. `phx plan [<repo>] [--json]` prints it all. Fixtures copied from MM3, CL, OCC and YTPL2 plus a synthetic sample plan; 108 new tests, 100 % branch coverage of `plan.py`. ADR-0013. Dev dependency `coverage`.
- Phase 03: hands-off `/phase` contract version 1 (`docs/PHX_AUTO_MODE_CONTRACT.md`, ADR-0012): `--auto` / `PHX_AUTO=1` trigger, block-with-question, `refused` outcome, `PHX-RESULT` line grammar, Gate column rules, lock paths for the manual-run guard, risk rule and git-authority wording, and a manual check procedure. This repo's `/phase` now carries `PHX-CONTRACT: 1`, a PHX-running check (step 0) and a hands-off section; shared instructions gain §1b. The `phased-project` skill templates, `SKILL.md` and the playbook note carry the same rules.
- Phase 02: stdlib-only `phx` package (`uv`, `src/` layout, console script `phx`, `python -m phx`), CLI skeleton with stub subcommands (`preflight`, `run`, `resume`, `status`, `stop`, `log`, `answer`, `plan`) and `--state-dir`/`--verbose`/`--version`, state-path and `.phx/config.toml` loader (`paths.py`), redacting JSONL event logger (`logging.py`, `redact.py`), 35 tests, real CI (ruff, mypy strict, pytest on Python 3.12 and 3.14) and a pre-commit config with ruff and detect-secrets. ADR-0010 accepted.
- Phase 01: repository governance files (LICENSE, NOTICE, README, SECURITY, CONTRIBUTING, CODE_OF_CONDUCT, THIRD_PARTY_NOTICES), `.gitignore`, `.editorconfig`, `.github/` templates, Dependabot config and a placeholder CI workflow, and the `docs/PHX_ARCHITECTURE.md` skeleton.
- Phase 00: specification, decision log, implementation plan and phase prompts.
