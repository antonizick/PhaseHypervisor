# Security Policy

## Scope
PhaseHypervisor is a **local tool** that starts AI agent sessions (Claude Code) with **bypassed permissions** on its owner's machine, inside repositories under the owner's control. It is not a service, opens no network listener and has no multi-user mode. Security reports are in scope when they show that PHX could be made to act outside that boundary: leaking secrets, running content from a repo or agent output as commands, or acting on the wrong repository.

## Reporting a vulnerability
Please do not open a public issue. Email nick@antonizick.com with a description, reproduction steps and the PHX version or commit. If the repository is hosted on GitHub, you may use its private vulnerability reporting instead. Expect an acknowledgement within a few days; this is a personal project, so there is no formal SLA.

## Security baseline (spec §4.3, S1–S5)
- **S1, bypass permissions are local-only.** PHX runs only on the owner's machine, in repos under `/home/nick/Work`, and refuses to run as root. `phx run`/`resume` enforce both (Phase 07): the repo's main checkout must be under `$PHX_WORK_ROOT`, default `~/Work` (the override exists for tests and pilots), and the effective UID must not be 0. Phase sessions are confined to their repo and worktree by the `/phase` rules, and a risk-stop rule makes an agent stop and ask (or block the phase with the question recorded) when an action looks high-risk or irreversible.
- **S2, no secret leakage.** Everything written to logs passes through a redaction step, and PHX never reads or copies `~/.config/ai-provider/openrouter.key` itself. Session transcripts (`sessions/<phase>-<n>.jsonl`) and stderr tails are redacted line by line before they are written. To log which OpenRouter model serves a phase, the runner (Phase 05) runs `ai-provider env`, whose output contains the key: PHX keeps only an allowlist of non-secret variables (base URL, model mappings, token caps), redacts those too, and drops the rest unread, so the key is never logged, stored or passed on by PHX. Phase sessions get `ai-provider`'s environment from `ai-provider` itself, not from PHX.
- **S3, untrusted content.** Repo content, plan text and agent output are treated as data. PHX parses them with strict patterns and never evaluates them or passes them unquoted to a shell. The plan parser (Phase 04) only reads `main` through `git` with argument lists, matches text with regular expressions, and never runs a command found in a plan (the test command is only extracted). Verification (Phase 06, ADR-0015) runs the plan's test command only in a temporary clone of `main`, never through a shell: a small interpreter accepts `&&`, `cd`, `NAME=value`, quotes and globs confined to the clone, and refuses pipes, redirects, variables and command substitution. The test environment drops `PHX_AUTO` and API keys. The triage session that reads a stopped phase's messages has no tools (`--tools ""`, one turn, outside the repo), and its prompt marks that text as data, so text planted in a repo can at most change the wording of a summary. The only write PHX makes to a repo on its own is the `⛔ Blocked` status commit, under the claim protocol's preconditions.
- **S4, one writer.** A machine-wide lock plus a per-repo lock prevent two supervisors, or two phases of one repo, from running at once. Both are `flock` locks under `$XDG_RUNTIME_DIR/phx/` (directory mode 0700) held for the supervisor's whole life; a manual `/phase` sees the per-repo lock and stops (contract §8). `phx answer` refuses while a supervisor holds the lock and, like the `⛔` repair, only commits the plan file when the main checkout is on `main` with that file clean. `state.json` is written atomically with mode 0600.
- **Detached runs** (`phx run --detach`, Phase 07) get only an allowlist of environment variables (paths, locale, display and session-bus addresses, `PHX_WORK_ROOT`); API keys or tokens in the launching shell never reach the systemd unit. Notifications carry phase IDs, reasons and the triage summary (already redacted), never secrets.
- **S5, irreversible actions stay human.** Making a repository public, publishing a release and force-pushing shared history always stop for the owner.

Secrets and personal data are never committed; `.gitignore` and (from Phase 02) a pre-commit secret scan enforce this.

## Supported versions
Pre-release. Only the latest commit on `main` is supported.
