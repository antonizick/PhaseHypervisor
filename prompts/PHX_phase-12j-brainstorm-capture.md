# PHX Phase 12j: Brainstorm capture across the method, the timeline and PHX

**Model:** Opus 5.5 (`/model claude-opus-5-5`) · **Depends on:** 12i · **Branch:** `phase-12j-brainstorm-capture` · **Worktree:** `../PhaseHypervisor-phase-12j` · **Gate:** review

Most of Nick's projects start as a brainstorming document in the repo root (`NUN_Brainstorming.md`, `OWH_Brainstorming.md`, `Brainstorming Project 1111.md`): a timestamped transcript of him and an AI working out the idea before `/phased-project` runs. Today the method barely sees it. Phase 00 may read it as "the source", but nothing records what it contributed, the planning lane of the timeline only shows hand-written `Planning:` entries (so brainstorming appears on some projects, as "Brainstorming with Grok", and not on others), and an untracked brainstorm file in the root makes `phx`'s timeline refresh refuse to run. This phase makes the brainstorm a first-class input, documented and drawn the same way on every project.

## Decisions already made (ADR-0037)
- **Detection by convention, no configuration.** A brainstorm document is a Markdown file in the repo root whose name contains `brainstorm` (any case). A plan header line `**Brainstorm:** <path>` overrides it (any path, several allowed, comma separated). Companion drafts (`Plan Draft.md`, `<PREFIX>_Draft Plan.md`) are listed as sources but not timed.
- **Times come from the document, never retyped.** Entry headers of the form `**YYYY-MM-DD HH:MM**  <label>` (optionally followed by a zone) are the evidence. The generator groups entries into working bursts (a gap over 90 minutes starts a new one) and draws each burst in the Planning lane as `Brainstorming`, with the entry count in the table. A hand-written `Planning:` entry whose title contains "brainstorm" wins over the automatic items, so existing projects (P11) do not draw it twice.
- **Content is captured once, as a trace.** `/phased-project` adds a **Brainstorm trace** to the spec's Amendments (table: brainstorm item, stamp, disposition `Adopted → <ADR/spec/phase>`, `Deferred → <owner question>` or `Dropped: <reason>`), and a `- **Brainstorm:**` bullet in the Phase 00 Phase Log entry (source file, span, entries, count of items by disposition, "covered through <stamp>"). The vault note gets a short Brainstorm section linking the file. `/phase-add` reads only entries after "covered through", and records the same bullet in its planning entry. `/phase` reads the trace, and a phase that fulfils or changes a trace row updates it at close-out.
- **An untracked or edited brainstorm file never blocks the timeline refresh** (`phx`'s `_refresh` ignores untracked files and brainstorm paths when it checks for a clean `main`).
- The brainstorm file is **committed with the Phase 00 planning commit** (it is evidence), unless the owner says it must stay private; then it is listed in `.gitignore`, the timeline still reads it from the working tree, and `--check` notes that its times are not reproducible from git.

## Goal
On a project with a brainstorm document, `python3 scripts/phase_timeline.py --write` draws its sessions in the Planning lane, in the SVG and the Mermaid blocks, with no hand-written entry; `/phased-project`, `/phase-add`, `/phase` and `phx preflight` each read the brainstorm in the way described above; and the user can see where every brainstorm item went.
